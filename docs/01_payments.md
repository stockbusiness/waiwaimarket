# 01 決済・精算・返金

出典：v1.4 4.3、4.5、15章

## 4 3 決済とテナント精算

法律上の販売者は各テナントとする。本部はマーケット運営者として決済作成、販売手数料の徴収、返金受付、チャージバック対応、テナント精算を管理する。

決済サービスはStripe Connectを採用し、1決済1テナントを前提にDestination charges方式で実装する。PaymentIntentにはtransfer_data[destination]とapplication_fee_amountを設定する。販売者をテナントとする方針に合わせ、on_behalf_ofで対象テナントを指定する。実装可否はStripeの審査結果に従う。

テナントの連結アカウントはExpressアカウントとする。手動出金を本部側で制御するには、本部がテナントの出金スケジュールを設定できる必要があり、Standardアカウントではこれを行えないためである。on_behalf_ofを使用するため、連結アカウントには送金の受取側設定に加えて、決済の精算主体となるための設定（merchant configuration）を行い、オンボーディング要件に含める。

on_behalf_ofで変わるのは、決済の精算主体（購入者の明細書に表示される名称・住所、精算国、適用される手数料体系、出金タイミング）に限られる。返金額、チャージバック額、紛争手数料は、on_behalf_ofの指定の有無にかかわらず本部のStripe残高から引かれ、Stripeに対する責任主体は本部のままである。すなわちon_behalf_ofは「法律上の販売者＝テナント」を実現する手段ではない。法律上の販売者をテナントとするための契約・規約・表示の整理は、専門家確認の論点として別途扱う。

Destination chargesでは、決済成功時にテナント取り分がテナントのStripe残高へ直ちに移動する。手動出金（manual payouts）は、その残高を銀行口座へ出金する時期を制御する機能として使用する。本部が売上金を預かり続ける仕組みとして扱わない。

銀行口座への出金は、返品受付期間を経過し、未解決の返金・紛争がない注文を対象に月末締め・翌月15日払いで行う。Stripeが定める残高保持期限を超えないようにする。売上金を本部側で保持してからテナントへ移す必要が生じた場合は、Separate charges and transfersを別途再評価する。

テナントの本人確認とStripe Connectオンボーディング完了は、出店承認の必要条件とする。オンボーディング完了だけでは承認せず、本部の商品・事業者審査も通過した時点で出店可能にする。

返金は本部がStripe上で実行する。全額・部分返金とも、テナントへ移動済みの金額を戻すためreverse_transfer=trueを使用する。初期方針ではキャンセルされた取引の販売手数料も割合に応じて返すためrefund_application_fee=trueとする。テナント都合の欠品、商品不良、誤配送などで手数料を返さない運用を採用する場合は、出店規約へ明記したうえでフェーズ0に別途決定する。

返金してもStripeの決済手数料は戻らない。この手数料は販売手数料（application fee）とは別に負担者を決める必要があり、初期方針では購入者都合の返金は本部負担、テナント都合（欠品・商品不良・誤配送）の返金はテナント精算から控除する。最終的な扱いはフェーズ0で決定し、出店規約と精算明細の両方に反映する。

Destination chargesでは、返金額、チャージバック額、紛争手数料が本部のStripe残高から引かれる。本部はテナントへの移動額を取り消して回収し、残高不足時は出金保留、次回精算との相殺、契約に基づく請求を行えるようにする。テナント残高がマイナスになった場合の回収手段として、Stripeの自動引落し（debit_negative_balances：登録済み銀行口座からの引落し）を有効にすることを初期方針とし、出店規約に明記する。返金待ちや紛争に備える運転資金と運用手順も準備する。

法律上の販売者、Stripe上の事業主体、領収書・適格請求書の発行者、返金責任、収納代行・資金移動業、会計処理はフェーズ0で専門家に確認する。確認結果によってStripe方式、契約書、規約、画面表示を一致させる。

決済サービス固有の処理を注文本体へ直接書かず、決済アダプター層として分離する。


## 4 5 返品 キャンセル 領収書

返品送料は、商品不良・誤配送はテナント負担、購入者都合は購入者負担を規約の初期値とする。

テナント都合のキャンセル（欠品等）は全額返金と付与予定ポイントの取消で処理し、テナント別のキャンセル率としてKPIに記録する。

法律上の販売者をテナントとするため、領収書と適格請求書の発行者は対象テナントとする。本部はテナントから委託を受け、マーケット画面から電子発行できる機能を提供する。書面には販売者名、登録番号、税率別金額、マーケットが発行を代行したことを表示する。

本部による代行発行はインボイス制度の「媒介者交付特例」に該当する可能性が高い。同特例には本部・テナントの双方が適格請求書発行事業者であること、本部の登録番号を記載できること、本部がテナントに交付内容の写しを提供・保存すること等の要件があるため、出店審査でテナントの登録番号を必須とするかを含め、専門家確認の対象とする。発行方法と記載内容は確認後に確定する。


# 15 決定事項

## 15 1 本版で決定済み

| **項目** | **決定内容** |
| --- | --- |
| 販売者と決済上の精算主体 | 販売者＝テナント。Stripeではon_behalf_ofでテナントを精算主体として指定する。Stripeに対する責任主体は本部のまま。専門家確認とStripe審査で最終確定 |
| テナントのStripeアカウント種別 | Expressアカウント。本部が出金スケジュールを制御し、merchant configurationをオンボーディング要件に含める |
| 決済・精算 | Stripe Connect Destination charges、manual payouts、月末締め翌月15日払い |
| 返金 | 本部が実行し、reverse_transfer=trueでテナント移動額を回収する。初期は販売手数料も割合返還。Stripe決済手数料は購入者都合＝本部負担、テナント都合＝テナント控除を初期方針とする |
| テナント残高不足時 | 出金保留・次回精算との相殺・請求に加え、debit_negative_balancesによる自動引落しを有効化 |
| 購入時認証 | メール認証を主、LINEは連携ログインのみ |
| ポイント初期値 | 還元1％、利用上限50％、確定は発送＋14日、期限12か月固定、明細単位付与、最大剰余方式、FIFO消費 |
| ポイント利用時の負担 | 本部負担分は精算時に補填、テナント負担分は精算から控除 |
| 発行予算 | 基本還元は警告基準額を監視し継続。上乗せキャンペーンは月次上限到達後に停止 |
| 技術構成 | Next.js／Supabase専用プロジェクト／Stripe Connect／Vercel／Resend |
| 在庫引当 | checkout開始時、TTL15分 |

## 15 2 フェーズ0で決定する

1. マーケットの正式名称と一般消費者向けブランド、ドメイン。

2. 基本還元の月次警告基準額と上乗せキャンペーンの月次発行上限。

3. 初期出店テナント、商品カテゴリー、配送方式。

4. 問い合わせ一次対応を本部とテナントのどちらが担うか。

5. 専門家確認とStripe審査の結果を受けた販売主体、決済方式、規約・契約書の文言。

6. テナント都合の返金時に販売手数料を返還するか、運営費として保持するか。

7. 返金時のStripe決済手数料の負担区分（初期方針：購入者都合＝本部、テナント都合＝テナント）の最終確定。

8. 適格請求書の代行発行方式（媒介者交付特例の要件充足と、テナント登録番号を出店必須条件にするか）。
