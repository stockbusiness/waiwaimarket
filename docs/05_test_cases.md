# 12 テスト必須項目

## 注文と決済

• 二重クリックでも注文・決済が重複しない。

• 決済成功後に通信が切れても注文が復旧する。

• 決済通知の順番が前後しても正しい状態になる。

• 在庫1点の商品を同時購入しても1件だけ成立する。

• 在庫引当が15分で解放され、解放後に他の購入者が購入できる。

• 全額・部分返金が正しく計算され、Stripe上の送金額と精算明細が一致する。

• 返金時にreverse_transferが実行され、テナントへ移動済みの金額が本部へ戻る。

• 販売手数料を返す場合にrefund_application_feeが正しく反映される。

• テナント残高不足時に返金・回収・出金保留が定めた状態へ遷移する。

• チャージバック発生時に本部残高、テナント回収額、精算明細が一致する。

• 返金時のStripe決済手数料が、購入者都合・テナント都合の区分に応じて正しい負担者の精算明細に反映される。

## ポイント

• 付与予定、確定、利用、失効、取消の残高が一致する。

• 同じ注文で二重付与されない。

• 同時に2画面から使用しても残高を超えない。

• 決済失敗・期限切れ時に予約ポイントが戻る。

• 部分返品時に利用ポイントと付与ポイントが明細単位で正しく再計算される。

• point_usage_allocationsから元ロット、有効期限、明細別使用数を再現でき、予約解除後にreleased行が残高計算に影響しない。

• 期限の近いロットから消費される。

• 利用上限50％を超える入力がサーバー側で拒否される。

• 確定バッチ・失効バッチを二重実行しても結果が変わらない。

• 管理者の手動変更に理由と実行者が残る。

• 基本還元は警告基準額到達後も継続し、上乗せキャンペーンは上限到達後に停止する。

## 権限と情報保護

• テナントは他店舗の注文・顧客・精算情報を閲覧できない（RLSとAPI認可の両方で検証）。

• テナント担当者は精算情報・事業者情報を閲覧できない。

• 配送先情報は必要なテナントだけが閲覧できる。

• 未承認商品は公開されない。承認済みの商品でも、テナントが未承認・停止中なら公開されない。

• テナントは自分の商品を承認できず、審査の所見を書き換えられない。

• テナントは在庫数を編集できるが、引当数は変更できない。

• 公開中の商品の本文（商品名・説明・カテゴリー）を直すと、もう一度審査に回る。

• 商品画像のパスが、自テナントかつ自商品のフォルダ直下に限られる。

• 公開の商品一覧で、カテゴリー・店舗・商品名のどの絞り込みからも未公開の商品が出ない。

• 商品名の検索語に `%` や `_` を入れても、ワイルドカードとして解釈されない。

• 販売しない設定の SKU が公開画面の価格と種類に出ない。

• 引当済みの在庫が「在庫あり」として表示されない。

• 公開していないサイト共通ページと、公開中でない版の本文が匿名から読めない。

• サイト共通ページの本文に書いた内容が HTML として解釈されない。

• 管理者操作が監査ログに記録される。

• サービスロールキーをクライアントから取得できない。

• 本部管理者は多要素認証なしで管理画面へ入れない。
